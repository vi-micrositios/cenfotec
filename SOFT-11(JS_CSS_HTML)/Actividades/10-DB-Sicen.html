Primera colección de SICEN con con Node.js y MongoDB (NestJS)

Objetivo: Programar en NestJS al menos una colección del modelo de datos de SICEN, con su esquema, DTO, servicio, controlador y módulo, creando solo los métodos que piden los requerimientos del cliente.

Contexto

En el ejercicio anterior, el equipo diseñó el modelo de colecciones de SICEN: entidades, atributos, tipos de datos, relaciones y la decisión de embeber o referenciar. Ahora ese diseño se convierte en código. Use su propio modelo: las tablas de atributos y el diagrama son la guía para escribir el esquema y las validaciones.

Igual que en el taller de gestión de personal, no se programa un CRUD genérico: cada endpoint debe responder a un requerimiento o caso de uso de SICEN.

Definir los requerimientos y los endpoints

Antes de escribir código, complete una tabla que relacione cada requerimiento con su endpoint. Primero el requerimiento, después la ruta.

Generar el módulo

Dentro de la carpeta del back-end, genere el recurso con el CLI de Nest. Use el nombre de la colección en plural y en kebab-case. 

nest g resource centros-educativos --no-spec
# What transport layer do you use?            → REST API
# Would you like to generate CRUD entry points? → n

Cree las carpetas que faltan para que la estructura quede así: 

src/centros-educativos/
├── schemas/
│   └── centro-educativo.schema.ts
├── dto/
│   └── crear-centro-educativo.dto.ts
├── centros-educativos.controller.ts
├── centros-educativos.service.ts
└── centros-educativos.module.ts

Escribir el esquema

Traduzca la tabla de atributos del ejercicio anterior a una clase con @Schema y @Prop. Cada fila de la tabla se convierte en un atributo, y cada regla en una opción de @Prop.

Escribir el DTO

El DTO valida los datos cuando llega la petición, antes de llegar a la base de datos. Sus reglas deben coincidir con las del esquema y con las validaciones del formulario que ya programaron con JavaScript.

Escribir el servicio

El servicio contiene la lógica y las consultas a MongoDB. Programe un método por cada fila de la tabla de la parte 1, usando el modelo inyectado con @InjectModel.

Escribir el controlador y el módulo

El controlador define las rutas: recibe la petición, toma los datos y llama al servicio. No contiene consultas a la base de datos. El módulo une todas las piezas.

Probar los endpoints

Use Thunder Client o Postman para probar cada endpoint.
