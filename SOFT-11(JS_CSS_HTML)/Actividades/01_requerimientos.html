Ejercicio 1: Especificación de requerimientos, historias de usuario y prototipado – CampusFest

Objetivo: Aplicar técnicas de especificación de requerimientos, redacción de historias de usuario y prototipado para transformar necesidades de un producto en requerimientos funcionales, sus historias de usuario y un prototipo que los represente visualmente para el sistema CampusFest.

Identificar y redactar 3 requerimientos funcionales (RF)

A partir de las funciones esenciales del sistema CampusFest, identifique tres funciones esenciales y redáctelas como requerimientos funcionales, describiendo el comportamiento o acción que el sistema debe realizar. Utilice el siguiente formato para cada requerimiento:

ID: RF-001, RF-002, RF-003
Nombre: Título breve de la función.
Descripción: Explicación clara y concisa de qué hace el sistema.

Redactar historias de usuario

Por cada requerimiento funcional identificado en la Parte 1, redacte una historia de usuario incluya los criterios de aceptación de la historia como lista de verificación.

Ejemplo:

Historia de usuario: Consultar la agenda de actividades

Criterios de aceptación:

  • La agenda muestra todas las actividades con fecha, hora y lugar.
  • El usuario puede filtrar por tipo de actividad (taller, concierto, charla).
  • La información se actualiza en tiempo real.

Asegúrese de que los criterios de aceptación sean verificables y estén relacionados directamente con la historia.

Diseñar el prototipo

Diseñe un prototipo que demuestre cómo se implementan los tres requerimientos funcionales. El prototipo debe incluir:

  • Las pantallas o vistas necesarias para cada función.
  • Elementos de interacción (botones, formularios, listas, menús, etc.).
  • Los flujos o transiciones entre pantallas para completar cada requerimiento.
  • Notas o leyendas que indiquen a qué requerimiento (RF-001, RF-002, RF-003) corresponde cada pantalla o flujo.
Recuerde: La coherencia entre requerimientos, historias de usuario y prototipo es fundamental. Cada pantalla del prototipo debe estar claramente vinculada a un RF y a su historia de usuario correspondiente.
