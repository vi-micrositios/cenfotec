Ejercicio: Evaluación de accesibilidad web

Objetivo: Evaluar la accesibilidad de la página productos.html, mediante pruebas manuales, revisión del código HTML y análisis automatizado con WAVE, con el propósito de identificar posibles problemas de accesibilidad y documentar los hallazgos sin realizar correcciones.

Recurso de evaluación

Utilice la rama accesibilidad del repositorio del proyecto y concentre toda la evaluación específicamente en el archivo productos.html.

Archivo a evaluar:
productos.html

Realizar pruebas manuales de accesibilidad

Analice el comportamiento de productos.html desde la perspectiva de una persona que utiliza diferentes formas de interacción. Las pruebas deben realizarse de manera manual y los resultados deben quedar documentados.

Pruebas sugeridas:

  • Comprobar si los enlaces y botones tienen nombres o textos que permitan comprender su función.
  • Revisar si las imágenes poseen información alternativa cuando corresponde.
  • Observar si existen elementos que dependan exclusivamente del color para transmitir información.
  • Revisar la legibilidad y el contraste visual de los contenidos.
  • Comprobar si los encabezados permiten comprender la estructura de la página.
  • Identificar problemas de accesibilidad que puedan afectar la comprensión o interacción con los productos.

Importante: No se deben corregir los problemas encontrados. El objetivo de esta etapa es únicamente identificar, comprobar y documentar los posibles problemas de accesibilidad.

Resultado esperado: Registro de los problemas identificados durante las pruebas manuales, indicando el elemento afectado y una descripción del comportamiento observado.

Revisar el uso de etiquetas HTML

Inspeccione el código fuente de productos.html para determinar si las etiquetas HTML utilizadas contribuyen a una estructura semántica y accesible.

Aspectos a revisar:

  • Uso correcto de encabezados como H1, H2, H3, entre otros.
  • Uso adecuado de elementos semánticos como header, nav, main, section, article y footer.
  • Uso correcto de enlaces mediante <a> y botones mediante <button>.
  • Existencia y asociación adecuada de labels en formularios, si los hubiera.
  • Uso de atributos alt en imágenes.
  • Identificación de elementos HTML utilizados de manera incorrecta o poco semántica.
  • Identificación de posibles atributos ARIA utilizados de forma incorrecta, innecesaria o incompleta.
  • Revisión de la estructura jerárquica y semántica general del documento.
Resultado esperado: Una revisión documentada de las principales etiquetas y atributos relacionados con la accesibilidad, indicando cuáles presentan un uso incorrecto.

Evaluar con WAVE

Utilice la herramienta WAVE (Web Accessibility Evaluation Tool) para realizar una evaluación automatizada de productos.html.

Instrucciones:

  • Ejecute la evaluación de la página utilizando WAVE.
  • Identifique los errores reportados por la herramienta.
  • Revise los errores y determine cuáles requieren corrección.
  • Observe los elementos relacionados con contraste, estructura, navegación y contenido.
  • Documente los resultados sin realizar cambios en el código.

Nota: WAVE es una herramienta de apoyo y sus resultados deben analizarse. Un elemento marcado por la herramienta debe ser revisado para comprender el problema y determinar si realmente representa un hallazgo de accesibilidad.

Resultado esperado: Registro de los resultados obtenidos mediante WAVE, diferenciando los errores detectados y las alertas que requieran revisión.

Elaborar la lista de errores encontrados

Integre los resultados de las pruebas manuales, la revisión del código HTML y la evaluación realizada con WAVE en una única lista de hallazgos.

Para cada hallazgo registre:

  • Número del hallazgo.
  • Elemento o componente afectado.
  • Descripción del problema.
  • Tipo de evaluación: manual, código HTML, WAVE o varias.
  • Evidencia: captura de pantalla, fragmento de código o referencia al elemento evaluado.
  • Impacto observable: describa qué dificultad puede generar el problema, sin proponer una solución.

Restricción del ejercicio: El informe debe limitarse a identificar y documentar los problemas. No se deben modificar archivos, corregir etiquetas, cambiar atributos, alterar estilos ni implementar soluciones de accesibilidad.

Resultado esperado: Una lista consolidada y sustentada de los problemas de accesibilidad encontrados en productos.html, acompañada de evidencias.
