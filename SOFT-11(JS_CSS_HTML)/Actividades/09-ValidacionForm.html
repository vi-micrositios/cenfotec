Ejercicio: Captura y validación de datos con JavaScript

Objetivo: Capturar los datos del formulario de SICEN elaborado en el ejercicio anterior y validarlos con JavaScript, utilizando expresiones regulares, clases de CSS para indicar errores y aciertos, elementos creados dinámicamente y mensajes claros que ayuden al usuario a corregir sus datos.

Contexto

El cliente de SICEN necesita que los datos lleguen completos y correctos antes de guardarse. Trabaje sobre el mismo formulario que creó con Bootstrap (solicitud de información, creación de formulario censal, configuración de censo u otro).

Preparar el formulario para la validación

Revise el HTML de su formulario y ajústelo para que JavaScript pueda encontrar cada campo y mostrar sus mensajes.

Ajustes al HTML

  • Agregar novalidate a la etiqueta <form> y mantener required en los campos obligatorios.
  • Verificar que cada campo tenga un id único y su <label for="…">.
  • Agregar debajo de cada campo un <div class="invalid-feedback" id="error-…"> vacío.
  • Enlazar cada campo con su mensaje mediante aria-describedby.

Capturar los elementos y sus datos

Cree el archivo js/formulario.js. Al inicio, seleccione todos los elementos que va a necesitar y guárdelos en constantes.

Validar los campos

Escriba una función de validación por campo (o una función reutilizable) y una función que las llame a todas e indique si el formulario es válido.

Nota: las expresiones regulares deben guardarse en constantes con nombre y llevar un comentario que indique qué datos aceptan.

Mostrar los errores y los aciertos

La persona debe saber qué campo tiene un problema, qué está mal y cómo corregirlo.

Resultado esperado: al presionar el botón principal, cada campo con error queda marcado en rojo con su mensaje, los correctos en verde, y aparece un resumen con la lista de errores.

Agregar interactividad con elementos dinámicos

Importante: los campos creados con JavaScript también deben validarse. Recuerde buscarlos en el momento de validar, porque al cargar la página todavía no existen.

Probar la validación

Ejecute al menos 8 casos de prueba. Incluya datos válidos, inválidos y límite.
